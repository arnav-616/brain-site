A second brain that grows itself

I wanted one place that remembers everything I learn and build, and tells me each morning what needs me. So I built a knowledge graph that an AI agent maintains every day, and a 3D map anyone can explore.

What it does

Every note in my Obsidian vault is a node; every link between notes is an edge. Each morning a Claude agent reads my email, class files, GitHub repos and saved links, writes new notes in my own words, links them to what I already know, and writes a briefing: what needs me today, deadlines, the news I care about, and what my brain learned overnight. Then it republishes the public map.

On my laptop, the same brain is the center of a private app: sorted email, the people waiting on me, an internship tracker, health check-ins, a life timeline, spaced-repetition review, and a command bar where I can capture a thought, ask a question, or ask it to do something (I approve every change).

How it's built

  • Ingest: a scheduled Claude Code agent follows a written routine (a slash command in the vault), with each source handled independently so one failure never stops the run.
  • Export: a Node script parses the vault into a graph, computes topics, link suggestions and meaning-based similarity (TF-IDF, no AI cost), and generates a preview image for every public note.
  • Map: React and three.js with a bloom pass, a custom force that gives each topic its own region, and a camera that glides aside so panels never cover the brain.
  • Private app: a local API inside the dev server runs Claude Code jobs, streams their progress, and applies changes as git commits. Phones get in only with a secret key.

Privacy by design

My vault holds email summaries, school notes, and things I'd never publish, so the default is private. A note is public only if it says visibility: public. Links to anything else are stripped, and the export refuses to publish if any private title or line of text appears in the public data. CI checks it again on every push. The assistant can read but not write; email is drafted, never sent.

What I learned

  • Automation is only useful if you can trust it: undo, leak checks and approval steps mattered more than features.
  • Writing the agent's routine as plain instructions, then tightening them when it drifted (like dates written in words), works better than hard-coding every step.
  • Design for the moment of use: the home view changes between morning and evening because what I need does.
